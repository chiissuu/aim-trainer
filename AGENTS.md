# Instrucciones de trabajo para agentes

## Contexto obligatorio

- Al comenzar una tarea, leer `docs/Contexto.md` y `docs/Pendientes.md`.
- Consultar `docs/Decisiones.md` antes de cambiar una elección ya establecida.
- Tratar `README.md` como documentación pública y `docs/` como documentación de aprendizaje y seguimiento.

## Forma de trabajar

- Aplicar cambios incrementales, sencillos y defendibles para una misión introductoria de JavaScript.
- No añadir frameworks, librerías o dependencias salvo petición expresa del alumno.
- Explicar previamente cualquier cambio que afecte a la estructura, la configuración o el recorrido principal.
- Conservar la separación entre HTML, CSS y JavaScript.
- Mantener los nombres y comentarios en castellano de forma coherente.
- Evitar comentarios que repitan literalmente el código; documentar el motivo o el concepto relevante.
- No sustituir una solución comprensible por una más avanzada sin una necesidad concreta.

## Documentación al cerrar un bloque

- Actualizar `docs/Pendientes.md` con tareas terminadas, tareas nuevas y bloqueos.
- Modificar `docs/Contexto.md` si cambia el funcionamiento o la estructura.
- Añadir a `docs/Decisiones.md` solo decisiones relevantes con su alternativa descartada.
- Crear una nota en `docs/Sesiones/` para hitos, errores significativos o cierres de fase.
- Actualizar el README cuando cambien funcionalidades, comprobaciones, uso de IA o autopsia.
- Marcar una comprobación como terminada únicamente si se ha ejecutado o el alumno ha confirmado el resultado.

## Git

- El alumno ejecuta personalmente `git add`, `git commit` y `git push`.
- Al cerrar un avance, indicar los archivos modificados y proponer un mensaje de commit.
- No incluir `.obsidian/`, archivos temporales ni pruebas auxiliares en el repositorio.
